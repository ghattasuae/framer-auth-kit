# Supabase Schema

This guide explains the database schema generated by framer-auth-kit and how to configure Supabase for email OTP authentication.

## Running the Migration

1. Open your Supabase project dashboard.
2. Go to **SQL Editor**.
3. Paste the contents of `supabase/migrations/001_auth_setup.sql`.
4. Click **Run**.

## Tables

### profiles

Extends the built-in `auth.users` table with application-specific fields.

| Column       | Type          | Default     | Description                    |
|-------------|---------------|-------------|--------------------------------|
| `id`        | uuid (PK)     | -           | References `auth.users(id)`    |
| `email`     | text          | -           | User's email address           |
| `full_name` | text          | -           | User's display name            |
| `avatar_url`| text          | -           | URL to user's avatar           |
| `role`      | user_role     | `'member'`  | One of: admin, member, guest   |
| `created_at`| timestamptz   | `now()`     | Account creation timestamp     |
| `updated_at`| timestamptz   | `now()`     | Last update timestamp          |

A profile is automatically created when a user signs up, via the `handle_new_user()` trigger function.

### user_rules

A flexible key-value system for per-user access flags. Use this to gate features or content for individual users.

| Column       | Type    | Default    | Description                        |
|-------------|---------|------------|------------------------------------|
| `id`        | uuid (PK)| auto      | Random UUID                        |
| `user_id`   | uuid (FK)| -         | References `profiles(id)`          |
| `rule_key`  | text    | -          | Rule identifier (e.g., "can_export") |
| `rule_value`| boolean | `false`    | Whether the rule is enabled        |
| `created_at`| timestamptz | `now()`| Creation timestamp                 |

**Example usage:**

```sql
-- Grant a user access to premium content
INSERT INTO public.user_rules (user_id, rule_key, rule_value)
VALUES ('user-uuid-here', 'premium_access', true);

-- Check if a user has a rule
SELECT rule_value FROM public.user_rules
WHERE user_id = 'user-uuid-here' AND rule_key = 'premium_access';
```

## Roles

The `user_role` enum defines three roles:

- **admin** - Full access to all profiles and user rules
- **member** - Default role for new users; can view and update their own profile
- **guest** - Restricted role; can view and update their own profile

## Row Level Security (RLS) Policies

All tables have RLS enabled. The following policies are applied:

### profiles

| Policy                              | Operation | Rule                                      |
|-------------------------------------|-----------|-------------------------------------------|
| Users can view own profile          | SELECT    | `auth.uid() = id`                         |
| Users can update own profile        | UPDATE    | `auth.uid() = id`                         |
| Admins have full access to profiles | ALL       | User's role is `admin`                    |

### user_rules

| Policy                                  | Operation | Rule                                  |
|-----------------------------------------|-----------|---------------------------------------|
| Users can view own rules                | SELECT    | `auth.uid() = user_id`               |
| Admins have full access to user_rules   | ALL       | User's role is `admin`               |

## Enabling Email OTP in Supabase

Before setting up SMTP, make sure OTP sign-in is enabled:

1. In your Supabase dashboard, go to **Authentication > Providers > Email**.
2. Ensure **Enable Email provider** is toggled on.
3. Ensure **Confirm email** is toggled **off** (OTP codes handle verification).
4. Optionally adjust the OTP expiry time (default: 60 seconds).

## Setting Up Resend as Supabase SMTP Provider

Supabase uses SMTP to send OTP emails. To use Resend:

1. Go to your [Resend dashboard](https://resend.com/domains) and verify a domain.
2. Generate an API key with sending permissions.
3. In your Supabase dashboard, go to **Authentication > Email Templates** to customize your OTP email (optional).
4. Go to **Project Settings > Authentication > SMTP Settings** and toggle **Enable Custom SMTP**.
5. Enter the following settings:

| Setting         | Value                        |
|-----------------|------------------------------|
| Host            | `smtp.resend.com`            |
| Port            | `465`                        |
| Username        | `resend`                     |
| Password        | Your Resend API key (`re_...`) |
| Sender email    | `noreply@yourdomain.com`     |

6. Click **Save**.

Now Supabase will send OTP emails through Resend using your verified domain.

## Promoting a User to Admin

To make a user an admin, run this SQL in the Supabase SQL Editor:

```sql
UPDATE public.profiles
SET role = 'admin'
WHERE email = 'admin@example.com';
```

Or by user ID:

```sql
UPDATE public.profiles
SET role = 'admin'
WHERE id = 'user-uuid-here';
```

Admin users have full read/write access to all profiles and user rules via the RLS policies.
